# AI录音助手 - 架构设计文档（通用跨平台版本）

---

## ✅ v1 最终架构决策（已确认，权威版本）

> 本节为最终拍板方案，下方其余章节作为背景参考。凡与本节冲突处，以本节为准。

**方案：Tauri + 前端为主（frontend-centric）+ 用户自填密钥**

- **共享层（99% 复用）**：React + TypeScript 承载全部 UI 与业务逻辑
  （录音、转写、AI 调用、状态管理、历史存储）。
- **平台适配层 `adapters/`**：隔离各平台原生能力差异（HTTP、文件、存储）。
  - 桌面（Windows/Mac/Linux）：**Tauri 2**（几 MB 小体积，原生 HTTP 无 CORS）
  - 网页：同一套 React，Vite 构建（dev 用 Vite proxy 绕过 CORS）
  - 移动（后续）：React Native，复用 hooks/stores/providers，仅重写 adapter
- **AI 能力**：前端通过 HTTPS **直连** STT / LLM 提供商，**不打包 Python 后端**。
  - **v1 默认免费 Provider：Groq**（免费额度充足，OpenAI 兼容接口）
    - STT：`whisper-large-v3-turbo`　LLM：`llama-3.3-70b-versatile`
  - 备选：OpenAI（付费）等，通过 `providers/` 抽象一键切换。
- **密钥**：用户在设置里自填，仅存本地。v1 零后端；对外公开分发时再加代理层。
- **存储**：元数据 → localStorage；音频 Blob → IndexedDB（桌面后续可换 Tauri SQL）。

```
共享层 (React + TS, 99% 复用)
  components / hooks / stores / providers(AI) / lib
                     │
        adapters/ (平台原生能力接口)
        ┌──────────┼──────────┬─────────────┐
      Tauri       Web        RN(后续)
     (桌面)      (网页)      (移动)
        │
   AI: 前端直连 Groq / OpenAI (HTTPS)
   密钥: 用户自填, 存本地
   后端: v1 无需常驻 (对外分发时加云代理)
```

**为什么不打包 Python 后端**：桌面打包重(150MB+)、移动端跑不了、Web 需部署服务器
——三点都与"跨平台通用"目标冲突。AI 本身就是 HTTPS 接口，前端可直连。
下方 `Python FastAPI 后端` 相关章节 **v1 不实现**，保留为后续可选的云端方案参考。

## 平台适配层 (Adapters) 详细说明

### 为什么需要适配层？

不同平台有不同的能力：
- **文件系统访问**：Tauri / Electron / Web 方式不同
- **音频录制**：原生 API vs Web Audio API
- **窗口控制**：桌面应用有，Web 没有
- **本地数据库**：Tauri/Electron 用 SQLite，Web 用 IndexedDB

### 适配层接口设计

```typescript
// src/adapters/types.ts
export interface IPlatformAdapter {
  // 文件系统
  saveAudioFile(data: ArrayBuffer, filename: string): Promise<string>
  readAudioFile(filepath: string): Promise<ArrayBuffer>
  deleteFile(filepath: string): Promise<void>
  
  // 数据库
  initializeDatabase(): Promise<void>
  query(sql: string, params?: any[]): Promise<any[]>
  
  // 窗口
  minimize(): void
  maximize(): void
  close(): void
  
  // 系统交互
  openUrl(url: string): Promise<void>
  showNotification(title: string, body: string): void
}

// src/adapters/index.ts
import { getAdapter } from './platform-detector'
export const platform = getAdapter()

// 使用示例：
import { platform } from '@/adapters'
const audioPath = await platform.saveAudioFile(audioData, 'record.wav')
```

### 具体实现

**Tauri 适配（轻量级推荐）**：
```typescript
// src/adapters/tauri.ts
import { invoke, listen } from '@tauri-apps/api/tauri'
import { save } from '@tauri-apps/api/dialog'
import { writeFile, readFile } from '@tauri-apps/api/fs'

export const tauriAdapter: IPlatformAdapter = {
  async saveAudioFile(data, filename) {
    const path = await save({ defaultPath: filename })
    await writeFile(path, new Uint8Array(data))
    return path
  },
  
  async readAudioFile(filepath) {
    const data = await readFile(filepath)
    return data.buffer
  },
  
  // ... 其他方法
}
```

**Electron 适配**：
```typescript
// src/adapters/electron.ts
const { ipcRenderer } = window.require('electron')

export const electronAdapter: IPlatformAdapter = {
  async saveAudioFile(data, filename) {
    return await ipcRenderer.invoke('save-audio', {
      filename,
      data: Buffer.from(data)
    })
  },
  
  // ... 其他方法
}
```

**Web 适配**：
```typescript
// src/adapters/web.ts
export const webAdapter: IPlatformAdapter = {
  async saveAudioFile(data, filename) {
    const blob = new Blob([data], { type: 'audio/wav' })
    const url = URL.createObjectURL(blob)
    // 通过后端 API 保存或直接返回 URL
    return url
  },
  
  // ... 其他方法
}
```

## 核心流程图

### 1. 录音 → 转文字流程

```
用户点击"开始录音"
    ↓
[前端] 启动录音 (navigator.mediaDevices.getUserMedia)
    ↓
[前端] 发送 POST /api/recording/start → [后端]
    ↓
[后端] AudioService 初始化音频流接收
    ↓
[前端] 实时捕获音频数据，缓冲到本地
    ↓
用户点击"停止录音"
    ↓
[前端] 发送 POST /api/recording/stop (含音频数据)
    ↓
[后端] 保存音频文件到本地，创建Recording记录
    ↓
[后端] TranscriptionService 调用 Speech-to-Text API
    ↓
[后端] 返回转录文本
    ↓
[前端] 实时显示转文字结果
    ↓
[后端] 保存 Transcription 记录到数据库
    ↓
完成
```

### 2. AI处理流程

```
用户选择已转录的文本
    ↓
用户选择 "生成摘要" / "提取关键词" 等操作
    ↓
[前端] 发送 POST /api/ai/summarize (含文本 & prompt)
    ↓
[后端] AIProcessingService 调用 LLM API
    ↓
[后端] 处理响应，保存结果
    ↓
[前端] 展示处理结果
    ↓
完成
```

## 数据库设计

### Recording 表（录音记录）
```sql
CREATE TABLE recordings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    file_path TEXT NOT NULL,
    duration INTEGER,  -- 秒
    file_size INTEGER,  -- 字节
    status TEXT DEFAULT 'completed',  -- pending, processing, completed, failed
    error_message TEXT
);
```

### Transcription 表（转录结果）
```sql
CREATE TABLE transcriptions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    recording_id INTEGER NOT NULL,
    content TEXT NOT NULL,
    language TEXT DEFAULT 'zh-CN',
    confidence REAL,  -- 置信度 0-1
    transcription_api TEXT,  -- 使用的API (whisper, google, etc)
    duration INTEGER,  -- 处理耗时（秒）
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (recording_id) REFERENCES recordings(id)
);
```

### ProcessingResult 表（AI处理结果）
```sql
CREATE TABLE processing_results (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    transcription_id INTEGER NOT NULL,
    task_type TEXT NOT NULL,  -- 'summary', 'keywords', 'classification'
    result_content TEXT NOT NULL,
    ai_model TEXT,  -- 使用的AI模型
    prompt_used TEXT,
    tokens_used INTEGER,
    duration INTEGER,  -- 处理耗时（秒）
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (transcription_id) REFERENCES transcriptions(id)
);
```

## API 接口清单（FastAPI）

### Recording API
```python
POST /api/recording/start
    响应: { recording_id: int, status: "started" }

POST /api/recording/stop
    请求: { recording_id: int, audio_data: bytes }
    响应: { status: "saved", file_path: str }

GET /api/recording/{recording_id}
    响应: Recording 对象
```

### Transcription API
```python
POST /api/transcribe
    请求: { recording_id: int, language: "zh-CN" }
    响应: { transcription_id: int, content: str, status: "processing/completed" }

GET /api/transcription/{transcription_id}
    响应: Transcription 对象

GET /api/transcriptions?limit=10&offset=0
    响应: List[Transcription]
```

### AI Processing API
```python
POST /api/ai/summarize
    请求: { text: str, max_length: int = 200 }
    响应: { summary: str, tokens_used: int }

POST /api/ai/keywords
    请求: { text: str, top_k: int = 10 }
    响应: { keywords: List[str], scores: List[float] }

POST /api/ai/classify
    请求: { text: str, categories: List[str] }
    响应: { category: str, confidence: float }
```

### History API
```python
GET /api/history/all
    响应: List[HistoryItem]  # 包含recording + transcription + processing结果

DELETE /api/history/{recording_id}
    响应: { status: "deleted" }

POST /api/export
    请求: { format: "txt" | "md" | "json" }
    响应: 导出文件
```

## 技术选型说明

### 为什么选择这套技术栈？

| 组件 | 选择 | 原因 |
|------|------|------|
| 桌面应用框架 | Electron | 跨平台最成熟，支持后续网页版复用代码 |
| 前端框架 | React | 组件化、生态成熟、易于维护 |
| UI框架 | Tailwind CSS | 快速开发、易于自定义主题 |
| 状态管理 | Zustand | 轻量级、无template boilerplate |
| 后端框架 | FastAPI | 异步性能好、自动API文档、类型提示 |
| 数据库 | SQLite | 本地无需部署、支持导出、足够MVP需求 |
| Speech-to-Text | Whisper / Google STT | 支持多语言、免费额度充足 |
| LLM | Claude / GPT | 性能稳定、可申请免费额度 |

### 可插拔设计说明

- **AI服务**：通过 Config 配置，支持快速切换不同API供应商
- **音频格式**：支持 WAV、MP3、FLAC，转换模块可扩展
- **数据库**：SQLAlchemy ORM 封装，支持迁移到 PostgreSQL/MySQL
