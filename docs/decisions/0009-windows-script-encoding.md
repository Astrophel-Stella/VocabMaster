# 0009. Windows 启动脚本编码与健壮性改进

- 状态: 已采纳
- 日期: 2026-07-28

## 背景

Windows 批处理脚本 (`.bat`) 在处理 UTF-8 编码的中文注释时存在问题：
1. UTF-8 编码的中文字符在某些 Windows 环境下显示为乱码
2. 批处理脚本中的 `find` 命令语法不正确（使用了 `^` 转义字符导致匹配失败）
3. PowerShell 脚本使用了 `pwsh.exe`，但某些系统只安装了 `powershell.exe`
4. 脚本缺少错误处理和友好提示
5. 工作目录假设问题：脚本假设从项目根目录运行

## 决策

1. **批处理脚本使用 ASCII 编码**：将所有 `.bat` 文件改为使用英文提示信息，避免 UTF-8 编码问题
2. **PowerShell 脚本保持 UTF-8 编码**：`.ps1` 文件继续使用中文提示，因为 PowerShell 对 UTF-8 支持更好
3. **修复 `find` 命令语法**：使用 `findstr` 替代 `find`，并修正正则表达式
4. **添加 `chcp 65001`**：在批处理脚本开头设置 UTF-8 代码页（虽然对英文内容不必要，但作为最佳实践保留）
5. **使用绝对路径**：脚本通过 `%~dp0` 获取自身所在目录，然后定位项目根目录
6. **添加错误处理**：每个关键步骤后检查 `errorlevel`，失败时提供友好提示

## 理由

### 为什么批处理脚本使用英文？

1. Windows 批处理文件的编码问题复杂：
   - 默认使用系统代码页（中文 Windows 为 GBK/CP936）
   - UTF-8 编码文件在某些系统上显示乱码
   - 即使添加 `chcp 65001` 也可能存在字体或终端兼容性问题

2. 英文提示可以：
   - 避免所有编码问题
   - 更好的国际化支持
   - 兼容所有 Windows 版本

### 为什么 PowerShell 脚本可以保留中文？

1. PowerShell 对 UTF-8 支持更好：
   - 可以在脚本开头设置 `[Console]::OutputEncoding`
   - 现代终端（Windows Terminal、VS Code）对 UTF-8 支持良好
   - 用户可以选择使用 `.bat`（英文）或 `.ps1`（中文）版本

### 为什么使用 `%~dp0` 获取脚本目录？

1. 避免工作目录依赖
2. 用户可以从任何目录运行脚本
3. 脚本内部使用绝对路径导航

## 后果

### 好处

1. 脚本在所有 Windows 环境下正常显示
2. 错误提示更友好，便于用户排查问题
3. 脚本可以从任意目录运行
4. 更好的错误处理避免用户困惑

### 代价

1. 批处理脚本用户看到英文提示
2. 需要维护两套语言版本的脚本（`.bat` 英文，`.ps1` 中文）

### 建议

如果需要中文提示，优先使用 PowerShell 脚本：
```powershell
.\scripts\dev.ps1
.\scripts\stop.ps1
```

如果遇到 PowerShell 执行策略问题，使用批处理脚本：
```cmd
scripts\dev.bat
scripts\stop.bat
```
