# 0002. 前端为主,不打包 Python 后端

- 状态:已采纳
- 日期:2026-07-22(追溯自架构设计_v1 的 v1 决策)

## 背景

早期方案设想 Python FastAPI 后端处理录音/转写/AI 调用(见 `docs/_archive/`)。
但目标是"一套代码跨全平台"。

## 决策

**v1 不打包 Python 后端**;前端通过 HTTPS **直连** STT / LLM 供应商。业务逻辑(录音/转写/AI/存储)全部在 React + TypeScript 共享层。

## 理由

常驻后端与"跨平台通用"三处冲突:
- 桌面打包重(捆绑 Python 运行时 150MB+);
- 移动端跑不了 Python 后端;
- Web 需部署并维护服务器。

而 AI 能力本身就是 HTTPS 接口,前端可直接调用。

## 后果

- ✅ 极简:零后端、零运维、全平台一套逻辑。
- ✅ 可测性:业务逻辑集中在 TS,测试重心明确(mock 边界 = `providers/` 的 HTTP)。
- ⚠️ **密钥安全**:v1 密钥由用户自填、仅存本地。**对外公开分发 Web 版时会暴露密钥,届时需加一层云代理**(仅改适配层,业务不动)。
- ⚠️ Rust 侧因此无业务逻辑,暂无单测/变异测试需求。
